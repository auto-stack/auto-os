# 文件管理器：从 Explorer 现有基础吸收 Strata 等产品

日期：2026-10-22；建议 D，事实深度按条目标明。对应 `027-file-manager`。本轮没有安装或跑分竞品。

## 市场与产品分层

日用桌面文件管理是成熟基础需求：普通用户看重可发现、可恢复与默认关联；重度用户看重键盘、多选、批处理与搜索；管理员还需要远端位置、权限和挂载状态。首批机会是把这些任务与 AutoOS 的启动、阅读、终端接通，而不是复刻最多菜单。

| 代表 | 形态/开源证据 | 值得借鉴的设计 | 对 AutoOS 的取舍 |
|---|---|---|---|
| [Strata](https://github.com/lgse/strata) | Rust + GTK4/GIO；主体 MIT；README/源码抽样 B | 列/图标/列表导航、键盘优先、渐进搜索、独立预览、可取消工作 | 新项目且 Linux 专用；丰富预览和系统集成带来依赖/维护成本，不照搬 GTK UI |
| [Dolphin](https://apps.kde.org/dolphin/) / [源码](https://github.com/KDE/dolphin) | KDE/Qt 文件管理器；官方页 A，具体许可逐组件核查 | 官方列出的标签、多视图/分割、位置与扩展能力，作为成熟桌面完整度参照 | 首版不把全部高级配置塞进主界面；KDE 集成不能当跨平台 Auto API |
| [COSMIC Files](https://github.com/pop-os/cosmic-files) | Rust；仓库级 GPL-3.0；README A | 与 Rust 桌面生态相邻，适合作为窗口/文件选择/系统接入的下一轮源码对照 | Rust 语言相同不代表 libcosmic 组件可嵌 AutoUI；当前仅确认定位，未验证功能对等 |
| [Yazi](https://github.com/sxyazi/yazi) | Rust 终端文件管理器；MIT；README A | 异步 I/O、任务调度、预览、键盘和扩展；文档明确 public beta/可能破坏兼容 | 吸收任务与键盘模型，图形界面仍应让鼠标用户可发现；不把终端图像协议带入 GUI |

Strata 仓库描述中的“The best file manager on Linux”是作者定位，并非比较试验结论。GitHub 元数据创建时间为 2026-08-28；本次抽样固定到 `809e2f5244b24326a73514b071fe8f4cb530c6c1`。成熟度需再看真实操作、回归和发布维护，不能用星数或一句口号代替。

## Strata 的实现中真正可学习的部分

1. **搜索有边界**：固定版本的 [`src/services/search.rs`](https://github.com/lgse/strata/blob/809e2f5244b24326a73514b071fe8f4cb530c6c1/src/services/search.rs) 包含结果数、发布间隔、索引条目/深度/时间预算；README 说明后台遍历和渐进结果。取其“工作预算与不完整状态明确”的原则，不机械复制数值。其名称/路径搜索不能算文件内容搜索。
2. **动作有生命周期**：[`src/services/jobs.rs`](https://github.com/lgse/strata/blob/809e2f5244b24326a73514b071fe8f4cb530c6c1/src/services/jobs.rs) 明确排队、运行、取消中、成功、失败、取消及并发/历史限制。该文件是自定义动作任务入口，不能直接认定覆盖所有复制事务；AutoOS 应分别验证文件操作和扩展动作。
3. **预览进程隔离**：固定版本的 [preview-sandbox](https://github.com/lgse/strata/blob/809e2f5244b24326a73514b071fe8f4cb530c6c1/docs/preview-sandbox.md) 说明通过 Bubblewrap 运行复杂解析器并限制输入/输出/时间资源。AutoOS 可借鉴 worker 边界；Windows、Vue 与 Linux 的具体隔离机制必须分别设计。
4. **平台现实清楚**：[`Cargo.toml`](https://github.com/lgse/strata/blob/809e2f5244b24326a73514b071fe8f4cb530c6c1/Cargo.toml) 明确 GTK/GIO、图像和媒体依赖。主体 MIT 不代表完整二进制都为 MIT：默认 `rar` 功能引入 UnRAR，README 明示其 non-free 性质；引入归档能力需单独选择构建与依赖。

## 与当前 AutoOS 基础的差距

本地可读证据：`apps/027-file-manager/README.md`、`SPEC.md`、`docs/REQUIREMENTS.md` 和 `docs/DESIGN.md`。已有产品方向本来就吸收 Finder/Explorer/Commander/Everything/Directory Opus，不应推倒重来。

| 维度 | 当前文档记载 | 下一步建议 |
|---|---|---|
| 大目录 | 快照/派生/渲染分离，渐进扩窗；快照上限 8000 | 保留，补真实首屏/输入延迟和内存测量；到上限明确提示；扩限另验框架 |
| 文件操作 | 多选、批量复制/移动/删除、同名冲突三选、分片传输/取消 | 先核验部分失败、断电/崩溃、权限、跨卷和回收站语义，再增加外观模式 |
| 搜索 | 目录子树递归，扫描上限诚实标注 | 把“当前目录过滤/子树搜索/全局索引”拆开；按数据规模决定常驻索引 |
| 预览 | 文本头、图片、目录摘要、元信息 | 引入超时/取消/缓存失效；复杂格式解析器先隔离 |
| 导航 | 地址栏/面包屑、网格/列表、收藏、键盘 | 列视图、双文件面板、标签是可选增强，现有需求明确在范围外；另 Plan 决定 |
| 桌面关联 | open_with / 路径传入已有规范 | 实测已运行 app、未运行 app、外部默认应用和失效路径四种情况 |

## 综合设计建议

默认单内容面 + 位置侧栏 + 面包屑/地址输入 + 可切换预览。列表/网格优先，列视图待深层目录试用再决定；双面板可作为高阶模式。键盘与鼠标共享同一动作集，明确焦点、选择与目标目录，避免快捷键暗中使用上次目录。

底部/任务面显示真实传输、冲突和失败。回收站删除与永久删除分开；只在实际可逆时显示撤销。移动中途失败应报告已完成/未完成项，取消不声称回滚已完成文件。远端/GVfs/网络位置作为 provider 的后续扩展，不能把 URI 当本地路径字符串拼接。

共享预览服务供 Explorer、Launcher、桌面资料盒、Photos/Reader 使用；其中服务对象应是有身份/版本的资源引用，别让几个 app 分别缓存一份不知何时过期的路径。文件系统为真值，UI 派生索引可重建。

## 实现方案与先行验证

**首选**：继续 Auto `.at` 的应用层/AutoUI 交互，用现有 FS 能力；发现无法达成的枚举、watch、异步、回收站或隔离缺口后，在 auto-lang/系统服务所属仓独立立项，app 中不新增手写 Rust 后端。Strata/Yazi 的代码不是直接整体移植目标。

**替代**：短期显式集成 Dolphin/Strata 作为高级文件操作工具，需完成外部窗口/默认关联/权限的集成门；不能用外部工具运行成功宣称 Explorer 已有相同功能。

先行场景：10k/100k 合成目录的首屏与选择；快速切目录丢弃过时结果；同名、只读、磁盘满、中途取消、跨卷、非 ASCII/长路径、符号链接环；预览损坏图片/超大文本/解析超时；复制后逐文件校验。用户数据不作为破坏性实验对象。输出 p50/p95、内存峰值、失败/取消后磁盘状态和双端差异，不预填“最快”的结论。

转实施前应先完成已有 PLAN-001..006 的统一复审或核对其最新复审结果；本研究不能覆盖原验收门。

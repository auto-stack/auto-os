# AutoIME Windows 版详细设计

2026-11-17 · 设计 05 · r1 · Windows 11 x64 日常试用版目标设计

AutoIME 通过 Windows 文本服务框架（TSF）向系统注册，以 librime 处理拼音和选词，用原生 Win32 绘制候选窗。日常试用版交付一套默认的简体拼音方案，支持全拼、简拼、全简混输、中英项目术语和本地用户学习。输入法可以脱离 AutoOS 独立使用；AutoEdit 是集成宿主，AutoUI、AGE、ACE 和 Linux 桌面均不构成开发前置。

## 3. 系统边界与调用合同

| 所有者 | 输入 | 输出与生命周期 |
|---|---|---|
| TSF 文本服务 | 激活、焦点、输入范围、按键、宿主终止组合及布局变化 | 管理编辑上下文、组合范围、编辑锁、原选区恢复及上下文代次。宿主拥有正文与选区。 |
| Rime 适配器 | 当前会话、键符、修饰位和按下／释放状态，或当前页选词动作 | 每次有效操作只推进引擎一次，取走一次提交，并返回一份操作后的快照。纯读取不消费提交。 |
| 候选窗 | 同一快照中的页号、页内顺序、标签、高亮、注释、末页标志、光标矩形 | 不激活编辑焦点。选择动作携带会话代次、页版本和页内索引；陈旧点击失效。 |
| 方案部署 | 只读公共词库、AutoIME 方案、项目词表、用户短语 | 编译并校验数据，发布可用版本；个人学习数据独立存放。按键路径只消费已部署资源。 |

实现沿用 [TSF 文本服务](../../experimental/autoime/windows/ime/textservice.cpp)、[引擎适配器](../../experimental/autoime/windows/ime/rime_engine.cpp)和[候选窗](../../experimental/autoime/windows/ime/candidate_window.cpp)。同一进程共享一次引擎初始化；每个活动编辑目标持有自己的会话。焦点离开时结束该轮组合、递增代次，释放旧引用。只有活动宿主、上下文和代次均匹配的回调可以改写正文。

快照另外携带预编辑串及其光标或选区、提交文本存在标志、选择键与显示标签。协议里分别标明引擎 UTF-8 字节偏移和 Windows UTF-16 偏移，在适配器统一转换。含 emoji 的正文和前后缀不得因索引换算而被截断。一次按键既有已提交前缀又有剩余组合时，先写入前缀一次，再在其后开启新组合。

## 4. 按键与编辑行为

### 4.1 Windows 按键分发

优先采用 PIME 式分工：在 Test 回调中根据焦点、模式、现有组合和方案键表判断是否接收，禁止在这一阶段提交正文或学习词条；在实际 KeyDown 中处理。只有 KeyDown 的宿主走同一入口。若某类按键必须询问引擎才能准确决定是否消费，则按小狼毫思路缓存该次引擎结果，在匹配的实际回调中应用一次。缓存绑定上下文、方向、键、修饰位与消息轮次；失焦、取消、键释放或新消息到来即清除。长按产生的不同重复消息仍按正常按键处理。

| 输入 | 空闲状态 | 组合状态 |
|---|---|---|
| 字母、Shift＋字母 | 中文模式开始拼写；英文模式直通。保留大小写信息。 | 交给当前方案处理，支持 `DNA`、`AutoOS` 等混输；Shift 单击与 Shift＋字母分别识别。 |
| Ctrl/Super 快捷键、Alt 快捷键 | 默认交给宿主，例如 Ctrl+S、Ctrl+V、Alt+Tab。 | 同样保留宿主快捷键。只拦截方案明确声明且当前状态有效的组合，识别 AltGr 的字符输入。 |
| 空格、数字、方向键、翻页键 | 常规编辑动作由宿主处理。 | 空格选高亮项；当前页有效选择键选对应项；方向与翻页遵循方案和当前页，按键与窗口标签一致。 |
| 退格、Esc、Enter | 交给宿主。 | 退格编辑拼写；删到空或 Esc 时取消并恢复。默认 Enter 提交当前原始拼写一次，供临时英文或标识符输入；英文模式下保持宿主换行。 |

中文／英文模式切换使用明确配置，默认允许单击 Shift 切换。组合中主动切换按取消处理；Shift 与其他键配合或键盘自动重复时不得误切。敏感输入范围或宿主禁用 IME 时立即走直通路径。

### 4.2 选区替换、取消和失焦

| 事件 | 对正文和会话的处理 |
|---|---|
| 开始组合 | 获取实际选区，保存恢复所需的内容、方向与范围锚点，仅在会话内存保留。对于富文本优先使用宿主可逆组合；无法保证恢复格式时，保留原选区，在候选窗临时展示拼写，直至确认替换。 |
| 更新组合 | 在拥有编辑锁时只修改该组合覆盖的范围，光标跟随引擎位置。普通插入的原范围长度为零。 |
| 用户选词 | 在当前范围提交选中的正文一次，结束组合，光标落在已提交文本之后。取消、悬停、仅浏览候选均不向引擎伪造确认动作。 |
| Esc 或主动切窗 | 在旧上下文仍可编辑且组合仍由 AutoIME 拥有时，撤销此次预编辑，恢复原选区，清空引擎组合并隐藏候选。用户未确认的拼写不主动保存成正文。 |
| 宿主强制终止、关闭或锁竞争 | 将代次作废。如果宿主已接管范围，以宿主终态为准，禁止按历史偏移回写或借新窗口补写。可延迟的编辑请求持有独立数据，在执行前重新验证所有权。 |

例：从「甲旧词乙」选中「旧词」，输入 `ni` 后按 Esc，结果仍为「甲旧词乙」；在同一位置输入 `nihao` 并确认「你好」，结果为「甲你好乙」。已提交的前缀不参与下一轮取消。同步编辑被拒时检查请求结果和编辑会话自身结果。异步结果到达时如果目标已切换，直接释放。若引擎已给出提交而宿主写入失败，优先恢复组合状态；禁止向另一个目标重放或因重试双写。[TSF 编辑会话](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontext-requesteditsession)

## 5. 默认输入方案与词库

方案标识建议为 `autoime_pinyin`。在独立的新用户目录部署、显式选取方案、从新会话回读实际生效的标识。首次升级保留用户已有的显式选择；当前朙月简化字 `luna_pinyin_simp` 作为可选回退。开发机路径继续支持已有引擎和共享数据覆盖，发布时列出所需词库、版本、校验值、许可证及组件。仅仿照结构的原创术语表和实际再分发的上游资源分别记账。

| 数据 | 来源与处理 | 排序原则 |
|---|---|---|
| 通用中文 | 按雾凇组织常用字、基础词和扩展词。保留全拼、首字母简拼、全简混输。 | 由 librime 合并系统词与用户学习结果。`nh` 保留「你好」「内核」等歧义，文档不锁死相对名次。 |
| 项目术语 | 随版本维护小词表，带读音和基础权重，例如「增量编译」「高斯泼溅」。 | 参与普通拼音竞争；引入新术语不应全局压过同音常用词。 |
| 中英混合 | 英文与混合词独立配置，保留大小写和空格。例如显式别名 `ros2` 可产生 `ROS 2`。 | 中文模式优先合理中文匹配，完整技术标识允许精确匹配；缩写触发条件由方案定义。 |
| 用户指定短语 | 用户可编辑的独立文件，可增删和重新部署。 | 显式短码精确命中优先；没有显式指定时继续自然排序。 |
| 用户学习 | AutoIME 自有数据目录中的 librime 用户词典。 | 普通模式接受引擎原生学习；隐私模式隔离可写用户词典或使用禁学习方案，不能只在界面上隐藏学习结果。 |

首版不引入依据宿主正文的主动重排。当前正在组合的整串拼音可以组句；读取编辑器中已提交的上文属于另一项功能。万象式模型将来以可选资源加入，缺少资源时基础拼音仍能运行。决定是否默认启用时，同时考虑整句输入节省的选词次数、模型大小和首键延迟。

## 6. 候选窗、部署与隐私

**候选窗。** 默认 Win32 无激活窗口，显示预编辑、当前页候选、真实选择标签和高亮。采用每显示器 DPI，按当前光标所在显示器工作区翻转、夹边。窗口移动、缩放、翻页和布局变化要重新定位；点击候选也不得抢编辑焦点。优先调用 `GetTextExt` 获取折叠到光标处的范围，传入有效的矩形及 `BOOL clipped` 输出参数。现有原型把第四参数传为 `nullptr`，修正后再判断哪些宿主仍需回退。同一焦点内可短暂复用最近有效锚点；无布局时在布局更新后重试，仍无结果再查询同一前台宿主的系统 caret。禁止沿用上一窗口坐标。[Windows GetTextExt](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontextview-gettextext)

**启动与升级。** 在安装、方案更新或显式重新部署时准备词库，避免在首个 KeyDown 中同步等待维护线程。多个应用同时启动只触发一次部署。新资源在临时版本目录编译，成功后原子切换；已有组合用完原版本。失败保留最近成功版本，再尝试朙月，完全不可用时让按键直通。保留 PLAN-069 的 TSF 身份和用户当前默认输入法。升级核对实际注册路径与文件版本，已加载的旧 DLL 待宿主释放后清理；卸载默认保留用户词库，重新安装应能恢复。

**隐私。** 默认诊断只记录版本、状态码、故障阶段及汇总耗时。键码序列、拼音、候选正文、提交文本、选区原文均不写日志；自动回归使用合成语料。用户词条的本地学习是可控的产品数据，独立于诊断。密码框和声明为敏感的 TSF 输入范围直接交还宿主，不创建学习会话，不显示候选。失败诊断也遵守同一规则。首次升级提示原型曾使用临时明文日志，提供其位置与显式清理入口。

## 7. 实施顺序与验收

执行任务与验收记录归入 [PLAN-070 · AutoIME Windows 日常试用版](../plans/070-autoime-windows-daily-use.md)。

| 顺序 | 实施面 | 可复验结果 |
|---|---|---|
| 1 · Windows 编辑正确性 | TSF 回调、修饰键、选区恢复、焦点代次、隐私日志 | 自动驱动 Test→Test→Down、仅 Down、持续重复、切焦后迟到回调。每次物理编辑产生预期提交次数。以合成测试串检查默认诊断无输入内容。 |
| 2 · 方案与候选 | 引擎适配、默认方案及词表、候选标签、光标和 DPI | 在临时用户目录回放 `nh`、`nih`、`nihao`、项目术语、中英混输；按标签所选项与快照一致；短语删除重部署生效。 |
| 3 · 安装和恢复 | 独立数据、版本切换、缺资源、并发冷启 | 从新用户目录离线冷启；验证最近版本回退、明确故障直通、升级后个人短语仍在。分别记录首次部署耗时、就绪后按键到候选的中位数和 P95。 |
| 4 · 一轮集成人工验收 | 同一交付构建，记事本、浏览器普通文本框、AutoOS 中的 041 AutoEdit | 各输入一段合成开发笔记，执行选区取消／确认、中英混输、快捷键、半截拼音切窗、候选跟随。记录实际宿主、交付版本和失败动作，修复后只复验受影响路径。 |

人工验收集中于第 4 步。前期设计从源码决策；开发过程中回放用于发现实现回归。AutoEdit 宿主不可用时，单列兼容性待测项，原生 Windows 输入法能继续交付；待测项不能计作该宿主通过。分发到未安装小狼毫的机器、独立引擎服务、图形词组管理和可选语言模型均可沿上述接口扩展。现有实现入口见[原型目录](../../experimental/autoime/windows/README.md)，集成样例见 [041 AutoEdit](../../../auto-ui/examples/ui/041-auto-edit/README.md)。
